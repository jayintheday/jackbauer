# Silent-failure catalogue

Read only your axis. Each entry: **pattern** — *detect:* what to read or grep — *silent because* — *fix*. These are leads, not a checklist to tick: report only what the evidence supports, and report silent failures you find that aren't listed. Examples name common tools; translate each pattern to the stack in front of you (another agent framework, OS, scheduler or no-code platform has its own version of most of these).

## A. Instruction conflicts

1. **Contradictory layers.** Global `~/.claude/CLAUDE.md`, project `CLAUDE.md`, nested `CLAUDE.md`, `AGENTS.md`, skill bodies, subagent definitions and code-embedded system prompts give opposing orders ("always use tool X" vs "never browse"; "be concise" vs "include full sources"; two different output folders). — *detect:* collect every instruction source in the step's stack, extract imperative sentences, pair up ones about the same tool, path, format or behaviour. — *silent because:* the model picks one side per run, so output drifts rather than breaks. — *fix:* one owner per rule; delete the loser; scope project rules to the project.
2. **Run-time stack differs from author-time stack.** The author tested interactively in one directory; the scheduler runs from `$HOME`, `/`, or another cwd, so a different `CLAUDE.md` set loads (or none). `claude -p`, SDK and cloud runs may skip user settings, memory, or project files. — *detect:* the working directory in the plist/crontab/script vs where the instruction files sit; `--settings`, `--setting-sources`, `--add-dir`, `cwd=` in code. — *silent because:* it works every time the author runs it by hand. — *fix:* set cwd explicitly; pass settings/instructions explicitly in headless calls.
3. **Global rules leaking into automation.** A personal `CLAUDE.md` rule ("always ask before X", "use /browse for all web") or a memory index meant for chat applies to an unattended job, which then stalls, asks a question nobody answers, or uses a tool unavailable headless. — *detect:* imperative rules in global files that require a human, a GUI, or an interactive tool. — *silent because:* headless runs end "successfully" with a question as the output. — *fix:* exempt automation explicitly or run it with an isolated config.
4. **Stale references.** Instructions name paths, IPs, hostnames, model IDs, tools, MCP servers, skills or env vars that no longer exist. — *detect:* `test -e` every path; check named skills/MCP servers are installed; compare model IDs against current ones. — *silent because:* the agent improvises around the missing thing. — *fix:* update or delete; prefer env vars over hardcoded paths.
5. **Skills that can't reach their own references.** A `SKILL.md` points at a file not shipped beside it, or a relative path that resolves differently when invoked from elsewhere. — *detect:* every file named in a skill exists relative to the skill dir. — *fix:* ship it beside the skill or inline it.
6. **Overlapping triggers.** Two skills or subagents whose descriptions match the same request; the wrong one fires sometimes. — *detect:* compare `description:` fields for shared trigger phrases. — *fix:* sharpen descriptions so each owns distinct words.
7. **Unenforceable or conflicting output contracts.** A downstream step parses JSON/markdown headings/filenames that the upstream prompt only loosely requests, or two prompts specify different formats. — *detect:* the parser's expectations vs the producer's prompt. — *silent because:* parse failures often fall back to defaults or skip the item. — *fix:* structured output / schema validation and fail loudly.
8. **Rule sediment.** Long instruction files with rules added after each incident, some now contradicting newer ones or the model's defaults. — *detect:* very long always-loaded files; dated or incident-specific rules. — *fix:* prune; keep only rules whose deletion would change behaviour.

## B. Retrieval & tools

1. **LLM reading PDFs.** Scanned PDFs with no text layer, multi-column layouts, tables, footnotes and headers mangled on extraction; pages past a limit dropped. — *detect:* how PDFs enter the pipeline (Read tool, `pdftotext`, an MCP, a vector store); run `pdffonts`/`pdftotext` on a sample if available to check for a text layer. — *silent because:* the model summarises whatever text survived, fluently. — *fix:* extract with a dedicated tool and check page/character counts; OCR scans; flag low-yield pages.
2. **LLM reading CSV/spreadsheets.** Asking a model to count, sum, filter or join rows "by reading"; large files truncated; Excel sheets other than the first ignored; formulas read as cached or missing values. — *detect:* prompts asking for aggregates over tabular files without code execution. — *silent because:* plausible numbers come back. — *fix:* compute with code (pandas/duckdb/sql) and have the LLM narrate the result.
3. **Read/tool truncation.** File reads capped by lines or bytes, tool results truncated or saved to a side file the agent never opens, web pages clipped. — *detect:* large inputs vs tool limits; transcripts showing "truncated", "lines 1-2000", "output saved to". — *silent because:* the agent answers from the part it saw. — *fix:* chunk explicitly with coverage checks, or pre-process with code.
4. **RAG recall.** Fixed-size chunks that split tables or sections; embeddings never refreshed after source changes; top-k too small; no metadata filters; no "not found" path. — *detect:* chunking config, index build date vs source modified dates, retrieval k, prompt behaviour when nothing relevant returns. — *silent because:* the model fills gaps from its own knowledge. — *fix:* structure-aware chunking, re-index on change, larger k + rerank, instruct "say not found" and log empty retrievals.
5. **Restricted tools in headless runs.** `--allowedTools`, `permissions.deny`, permission mode, sandbox or missing MCP config block web search/fetch/Bash in the automated run. — *detect:* compare tools the prompt expects against the run's allow/deny lists and permission mode; grep transcripts for permission denials. — *silent because:* the agent answers from training data instead of searching. — *fix:* allow exactly the needed tools; make the prompt require citations so missing search becomes visible.
6. **Restrictions that don't restrict.** A tool allow-list covers built-in tools but not MCP servers (or the reverse), so the agent routes around the block through an unrelated MCP tool that can run commands or touch another service. — *detect:* which MCP servers load for the run (`--mcp-config`, `--strict-mcp-config`, project `.mcp.json`, user config) vs the intended tool list; unexpected `mcp__*` calls in transcripts. — *silent because:* the job still "works", just through a side door. — *fix:* load only the MCP servers the job needs; restrict MCP tools explicitly.
7. **Web search limits.** One query where research needs many; result snippets used as if they were full pages; no date filtering for "latest" questions; sites blocking automated fetch. — *detect:* search tool config, prompt wording, fetch errors in history. — *fix:* multi-query plan, fetch primary sources, record retrieval dates.
8. **Expired auth.** MCP OAuth tokens, API keys, cookies, Google/Notion/Slack tokens that expire; keychain-backed credentials unavailable to launchd/cron. — *detect:* auth errors/401/403 in logs; token files' dates; credentials read from keychain in an unattended job. — *silent because:* the step returns empty results instead of failing. — *fix:* health check that fails loudly; service tokens for automation.
9. **Answering from memory on tool failure.** Prompts lack "if the tool fails, stop and say so". — *detect:* tool errors followed by confident output in transcripts. — *fix:* require a sources/evidence field; treat an empty one as failure.
10. **Capture and scope filters that drop real work.** Path exclusions, allow-listed roots, minimum lengths and size limits that discard more than intended — often a comment says one thing and the code matches more; captured text truncated with no marker. — *detect:* read every filter and compare it with its comment and with real inputs (the items that exist at the source vs what reached the store); look for a counter of dropped items. — *silent because:* dropped items leave no record at all. — *fix:* narrow the filter, count drops by reason and surface the count, mark truncation.
11. **Partial reads from APIs.** Only the first page of a paginated API (Notion, Google, Slack, Airtable, GitHub…) is fetched; date-window queries miss items in a timezone gap; search APIs capped at N results treated as "everything". — *detect:* pagination cursors (`next_cursor`, `nextPageToken`, `has_more`) ignored in code or node settings; result counts that sit exactly on a page size. — *silent because:* a smaller dataset looks complete. — *fix:* loop the cursor; assert counts against a known total.

## C. Orchestration & reliability

1. **Scheduler environment.** cron/launchd/systemd/Task Scheduler lack your shell PATH, nvm/pyenv shims, `HOME`-relative config, keychain access, network on wake; laptop jobs skipped while asleep (cron) or fired late in a burst (launchd `StartCalendarInterval`). — *detect:* the plist/crontab vs the commands' locations; `StandardErrorPath` content; machine sleep patterns. — *fix:* absolute paths, explicit env, run on an always-on host.
2. **Swallowed failures.** `|| true`, `2>/dev/null`, bare `except: pass`, pipelines without `set -o pipefail`, exit code 0 after error, logs written to a path nobody reads or never rotated. — *detect:* grep scripts for those patterns; check the log path exists and is recent. — *fix:* fail with a non-zero exit, and route failures somewhere a human sees.
3. **No alerting / no heartbeat / alerts nobody receives.** Nothing tells anyone when a run doesn't happen at all; or the alert goes to a channel nobody watches (a fresh chat session, an unread log, a filtered inbox); or the prompt tells an unattended run to "stay quiet when there's nothing to report", so a multi-day outage ends quietly every run. — *detect:* is there any notification on failure *and* on absence of success (dead-man's switch), on a device the user actually looks at? Has one ever been delivered? — *silent because:* absence produces no event. — *fix:* heartbeat checked by something independent of the failing machine; test-fire the alert once.
4. **Caps, quotas and rate limits.** Daily processing caps, API rate limits, plan usage limits; when hit, work is skipped or deferred without a queue-depth alarm. — *detect:* constants like `MAX_PER_DAY`, 429s in logs, queue/backlog size over time. — *silent because:* the job "succeeds" each day while the backlog grows. — *fix:* alert when backlog grows N days running; prioritise; raise the cap or batch.
5. **Growing queues / stuck items.** Items that fail repeatedly stay at the head and block, or retry forever. — *detect:* oldest unprocessed item's age; items with high attempt counts. — *fix:* dead-letter after N attempts; report queue age.
6. **Overlap and races.** A run that takes longer than its interval starts a second copy; two machines run the same job; concurrent writers to the same file/vault/git repo. — *detect:* lock files, `flock`, run durations vs schedule, multiple hosts with the same job. — *fix:* lock, single owner, idempotent writes.
7. **Non-idempotent steps.** Re-runs duplicate notes, emails or rows; partial writes leave half-files that later steps treat as complete. — *detect:* write-then-rename? dedupe keys? — *fix:* atomic writes, idempotency keys.
8. **Unverified "success".** The agent says "done" and the pipeline believes it; no check the output exists, is non-empty, parses, or changed. — *detect:* what happens after each agent step. — *fix:* a cheap deterministic check after every agent step.
9. **Network and host dependencies.** VPN/Tailscale/SSH tunnels, a home server, a sleeping second machine. — *detect:* hostnames/IPs in configs; tunnel launch agents; connection errors in logs. — *fix:* pre-flight connectivity check that alerts.
10. **Drift from upgrades.** CLI/model/library updates change flags, output formats or defaults; hard-coded runtime paths (an interpreter installed only as another package's dependency, a version-manager shim, a container image tag) vanish on cleanup and the job fails before it can log. — *detect:* unpinned versions, `@latest`, auto-updating tools, model aliases; interpreter paths in schedulers and hooks vs what the package manager considers explicitly installed. — *fix:* pin, own the interpreter (venv or explicit install), smoke-test after upgrades.
11. **Health checks measuring the wrong thing.** "Stale" computed from the wrong timestamp (last success of anything, not age of the oldest pending item); error fields recorded but never read by the health check; "healthy" reported without reaching the thing it checks. — *detect:* read the health function line by line against what each state should mean; compare its verdicts with the run history. — *silent because:* the dashboard says OK, or it cries wolf until ignored. — *fix:* derive health from oldest-pending age, recent errors and last confirmed contact.
12. **Bots committing more than their own files.** `git add -A`/`-u`/`commit -a` in an automated sync sweeps in hand edits under a bot message. — *detect:* the sync's git commands; bot commits touching files the bot doesn't own. — *fix:* stage explicit paths only.
13. **No-code platforms that keep going.** n8n "Continue On Fail" / "Always Output Data", Make error handlers set to ignore/resume, Zapier steps with empty fallbacks, no error workflow configured, execution history pruned before anyone looks. — *detect:* export the workflow JSON/blueprint and read each node's error settings; check the error-workflow/notification settings and execution retention. — *silent because:* the run shows green with an empty item passed downstream. — *fix:* fail on error by default; one error workflow that alerts; keep failed executions.
14. **Hosted schedulers that stop by themselves.** GitHub Actions scheduled workflows disabled after 60 days without repo activity and delayed under load; free-tier hosts that sleep; platform cron limits (minimum interval, max duration, one region); serverless timeouts that kill long agent runs mid-way. — *detect:* the platform's schedule and plan limits vs the job's needs; last successful run dates in the platform UI/API. — *fix:* keep-alive or paid tier, a heartbeat (C3), split long runs.
15. **Time and schedule semantics.** Timezone and DST shifts (cron in UTC vs the user's local time, an hour skipped or run twice), "daily" windows that leave gaps or overlaps between runs, schedules that assume the machine is on. — *detect:* the scheduler's timezone vs the timestamps the job filters on. — *fix:* window by "since last successful run", not by wall-clock day.

## D. Context management

1. **Always-loaded bloat.** Huge `CLAUDE.md`/memory indexes/skill lists/MCP tool definitions loaded every turn of every run. — *detect:* size of each always-loaded file; number of MCP servers enabled for the automated run (each adds tool schemas). — *silent because:* it only costs money and attention, and dilutes rules. — *fix:* move rarely-needed material behind pointers; enable only needed MCP servers per job.
2. **Compaction losing rules or state.** Long runs that hit auto-compaction; the summary drops constraints or the task list. — *detect:* compaction events in transcripts; long single-session jobs. — *fix:* shorter sessions per item; durable state in files, not in the conversation.
3. **Handoff loss.** Orchestrator gives subagents thin prompts ("summarise this") without the goal, format, or constraints; subagents return prose the orchestrator re-interprets. — *detect:* subagent prompts in transcripts or code. — *fix:* full brief per subagent; structured returns.
4. **One context doing everything.** A single agent processes N documents in one window, so later items get less attention and earlier ones get forgotten. — *detect:* loops over items inside one prompt. — *fix:* one fresh call per item, aggregate with code.
5. **Re-reading the same large material every run.** Unchanged files or a whole vault reloaded instead of diffs. — *detect:* repeated large reads across runs. — *fix:* process changes since last run; cache derived summaries.
6. **Instructions buried mid-context.** Critical rules placed in the middle of long injected documents. — *fix:* put the task and constraints at the start and end, data in the middle.
7. **Rolling summaries that erase.** Each run rewrites a summary from the previous summary plus new input, so facts and decisions drop out version by version; hard caps (`[:8]`) slice lists; then the raw source is purged. — *detect:* diff successive versions of one summary in git history for facts that vanish without being superseded; count items sitting exactly at the cap; retention/purge settings for raw input. — *silent because:* each version reads fine on its own. — *fix:* append-only fields for decisions, dated delta sections, keep raw input until the summary is checked.
